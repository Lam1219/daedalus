# 1. How we build

## 1.1 Stack

- **Apps:** Android phone (`daedalus-companion`, Kotlin/Compose) and Wear OS watch (`daedalus-watch`), plus iPhone and Apple Watch (`daedalus-companion-ios`, SwiftUI, project generated by XcodeGen from `project.yml`). `daedalus-shared/` holds code shared by the Android apps.
- **Algorithms:** `daedalus_watch_kit/` (Python) is the reference. The Kotlin and Swift ports must match it on the golden vectors in `daedalus_watch_kit/golden/`.
- **Backend: Supabase only**, hosted in Canada, with migrations in `supabase/migrations/`. Sign-in, storage and processing all stay in Supabase. Cloudflare was considered and rejected (owner, 2026-11). **Reopen only if** Supabase cannot meet a data-residency or regulatory requirement.
- **Research scripts:** `python_scripts/`. The Parkinson@Home data in `dataset/` is covered by a data-use agreement and is never committed.

## 1.2 Owner's choices and installed packs

Skill defaults apply, with these departures:
- Backend is Supabase only (owner, 2026-11).
- On-screen wording is plain and calm. Use the words a person with Parkinson's would use (for example "pace", not "pulse"), in English and French.

Reviewers always have a fallback, never "none". Prefer another model family; use a fresh session of the builder's family when no other can run (`independent-review`). Precedence: current session owner instruction > this file > user-level instructions > skill defaults.

Installed packs (Claude Code, project settings): `product`, `ai-shipping`, `agent-teams`, `agent-harness`, `app-stack`, `work-humanizer`. They update themselves. Project review agents live in `.claude/agents/`: `ios-reviewer`, `android-reviewer`, `ux-reviewer` and `review-orchestrator`. The orchestrator must run as the main session: `claude --agent review-orchestrator`.

## 1.3 Testing

- **Python kit:** `cd daedalus_watch_kit && python -m pytest` must pass before any change to an algorithm or its ports.
- **Android:** `./gradlew assembleDebug` (and `./gradlew test`) in `daedalus-companion` and `daedalus-watch`.
- **iOS:** `cd daedalus-companion-ios && xcodegen`, then build the **Daedalus** scheme. Haptics, heart rate, wrist motion and WatchConnectivity file transfers only work on real devices, so say what a simulator could not check.
- Read the exit code from the log, not from a notification. A report inherited from another session is a claim: re-run the check yourself before repeating its result.

## 1.4 Working rules

- Read this file before the first plan.
- **Apply skill defaults without asking.** Get the owner's clear go each time before anything irreversible or outward-facing: production Supabase, an App Store or Play release, publishing, spending money, or deleting anything public. Questions about what the product should do belong to the owner.
- **Tests and doc lines are part of the change.** A bug fix lands with a test that fails before the fix.
- **If a doc disagrees with code you did not change, say so in the summary.** The owner decides which side moves.
- **No play-by-play.** Plan, build, then summarize once.
- **Write commit messages through a heredoc (`git commit -F -`), never `-m "…"`.**
- **Every user-facing change ships on all four apps,** or the summary names the app that lags and why.

# 2. This product: Daedalus

## 2.1 What it is

A freezing-of-gait companion on the watch people already own (Apple Watch and Wear OS), with its phone apps. The person taps "I'm stuck" and the watch plays a stepping beat at their own cadence. It also has breathing and posture tools, medication reminders and a journal shared with the care team. It starts as a wellness app; freezing detection and automatic cueing come later as software as a medical device, Canada first.

## 2.2 Users

People with Parkinson's who freeze, their caregivers, and their physiotherapists and neurologists (the channel and later the prescribers). Each person signs in with a Supabase account.

## 2.3 Not in scope

Dose recommendations (clinical decision software), a vibration cue for tremor (no evidence it helps), and any disease claim in R1.

## 2.4 Constraints on the data

Health data is hosted in Canada and follows PHIPA and Quebec's Law 25. A person can delete their data and account from the app. Data-program data needs its own ethics-approved opt-in consent.

## 2.5 Status

Working prototypes exist on all four apps. The automatic-cues work (guard engine in shadow mode) is on `feature/automatic-cues`. The revamp proposal was accepted on 2026-11-13 (direction A, `docs/product/proposal.html`). New features are paused until the home pilot and interviews report (`docs/product/plan.md`).
